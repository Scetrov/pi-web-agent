## Learnings

- The design’s NDJSON reader used `for await (const chunk of textStream)`, but current TS DOM typings in this repo rejected async iteration on `ReadableStream<string>` during `pnpm build`. The working adaptation is in `web/pi-web-ui/src/lib/ndjson.ts:8-37`, which still uses `TextDecoderStream` but reads via `getReader()`.
- Phase 5 manual tests all passed in browser-tools: token paste loaded metadata, title save persisted across reload, reset changed visible `sessionId`, and the status strip showed cwd/model/thinking/tokens/resource summary.
- Phase 6 manual smoke also passed: sending a prompt immediately appended the user message, assistant output finalized into transcript, usage tokens refreshed in the status strip, and reset cleared transcript/current run while allocating a new `web_*` browser session id.
- Port `4317` was already occupied by another local `pi` process during testing, so manual verification used a temporary Pi instance on `4318` by setting `PI_WEB_PORT=4318`. The temporary process was shut down afterward.
- Useful runtime anchor for backend route behavior remains `.pi/extensions/web-agent/index.ts`, especially `/api/chat/stream`, `/api/chat/abort`, and `/api/session/reset`.
