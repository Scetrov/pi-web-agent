## Learnings

- The repository still is **not a git repository** in the current working directory. `git branch --show-current`, `git rev-parse --short HEAD`, and prior `git status` checks produce no usable branch/commit metadata; use `unknown` for commit/branch unless this changes.
- Phase 1 and Phase 2 files were re-read/verified before implementation and remain present: `.pi/extensions/web-agent/{config.ts,types.ts,browser-loader.ts,session-store.ts,auth.ts,meta.ts,static.ts}` plus `web/pi-web-ui/src/{types/chat.ts,lib/title-heuristic.ts}`.
- The stream protocol must remain the explicit browser-facing union from `.pi/extensions/web-agent/types.ts` and `web/pi-web-ui/src/types/chat.ts`; do not pass raw `AgentSessionEvent` objects to the browser.
- `/health` intentionally remains outside auth in `.pi/extensions/web-agent/index.ts:92-102`; all `/api/*` routes are protected by `.pi/extensions/web-agent/index.ts:105-108`.
- Reset semantics continue to allocate a fresh `web_*` session id through `WebSessionStore.resetSession()`; the reset route returns only `{ sessionId }` at `.pi/extensions/web-agent/index.ts:146-155`.
- Static/file-inspection verification passed for Phase 3. A TypeScript compiler check was attempted but this repo has no local TS/Node type setup, and `npx tsc` resolves to the wrong package unless TypeScript is installed. This is not one of the plan's Phase 3 success criteria.
- `static.ts` still may throw if `web/pi-web-ui/dist/index.html` is absent. That is expected until later frontend phases create/build the SPA, but non-API browser routes can surface 500s before Phase 4/6 output exists.
- Minor non-blocking hardening opportunities observed by review: malformed JSON currently becomes a 500 via the top-level catch instead of 400; `server.listen()` port-conflict errors are not specially handled; request body shape validation is minimal for `sessionId`/`prompt`.
