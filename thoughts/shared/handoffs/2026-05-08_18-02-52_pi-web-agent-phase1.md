## Learnings

- This repo is **not a git repository** in the current working directory, so branch/commit metadata fell back to `unknown` and `git status` was unavailable.
- The backend and frontend stream vocabularies now match exactly on event names; if future phases add protocol logic, preserve the Phase 1 contract defined in `.pi/extensions/web-agent/types.ts:79-124` and `web/pi-web-ui/src/types/chat.ts:85-130`.
- The loader filter is intentionally narrow: it excludes only the resolved web-agent extension entry path, not all extensions. See `.pi/extensions/web-agent/browser-loader.ts:14-24`.
- Reset semantics are already aligned with the design: dispose old session, then allocate a new `web_${randomUUID()}` id. See `.pi/extensions/web-agent/session-store.ts:110-121` and `.pi/extensions/web-agent/session-store.ts:134-141`.
- `buildWebAgentConfig()` already establishes the key defaults future phases depend on: loopback host, port `4317`, one-hour idle TTL, generated token fallback, static root `web/pi-web-ui/dist`, and restrictive security headers. See `.pi/extensions/web-agent/config.ts:5-10` and `.pi/extensions/web-agent/config.ts:35-76`.
