## Learnings

- The repository still is **not a git repository** in the current working directory. `git status`, branch, and commit metadata are unavailable; use `unknown` for commit/branch unless this changes.
- Phase 1 implementation remained present and aligned when resumed: `.pi/extensions/web-agent/{config.ts,types.ts,browser-loader.ts,session-store.ts}` and `web/pi-web-ui/src/{types/chat.ts,lib/title-heuristic.ts}`.
- Phase 2 was implemented from the design, with one small hardening improvement in `.pi/extensions/web-agent/static.ts:22-30`: traversal detection uses `relative(root, candidate)` and rejects `..` / `../...` instead of a raw string `startsWith(root)` path-prefix check. This avoids false positives for sibling directories with a common prefix.
- `/health` is still only planned for Phase 3 route wiring and intentionally remains outside auth. Phase 2 only provides helpers/static serving that future `index.ts` will call.
- `auth.ts` applies whatever `securityHeaders` come from `buildWebAgentConfig()`. Those include `cache-control`, `content-security-policy`, `x-frame-options`, `referrer-policy`, and `x-content-type-options` from `.pi/extensions/web-agent/config.ts:58-75`.
- `meta.ts` intentionally uses Pi session/resource APIs instead of duplicating state: `session.sessionName`, `session.model`, `session.thinkingLevel`, `session.getActiveToolNames()`, `session.getAllTools()`, `session.getSessionStats()`, and loader getters for extensions/skills/prompts/themes/context files.
- Verification for Phase 2 was static/file-inspection only. No runtime HTTP server exists yet because `.pi/extensions/web-agent/index.ts` belongs to Phase 3.
