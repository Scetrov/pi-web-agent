# Recreate the Pi Web Agent

## Overview

Implement the Pi Web Agent described in `thoughts/shared/designs/2026-05-08_17-08-27_pi-web-agent.md`: a project-local Pi extension under `.pi/extensions/web-agent/` plus a Vite/React SPA under `web/pi-web-ui/`. The backend owns loopback HTTP serving, token auth, browser-session lifecycle, metadata, static asset serving, and Pi-event-to-NDJSON translation. The frontend owns token/session persistence, transcript/current-run state, title fallback, status strip, and Send/Stop/Reset controls.

The design explicitly approved six ordered slices. No phases are parallel because later files deepen or depend on earlier protocol/state vocabulary.

## Desired End State

- Pi auto-discovers `.pi/extensions/web-agent/index.ts` and starts a loopback bridge at `127.0.0.1:4317` by default.
- `/health` is public; `/api/*` requires `x-pi-web-token` checked with timing-safe equality.
- Browser sessions are isolated in memory by browser `sessionId`, using `SessionManager.inMemory()` plus `DefaultResourceLoader` filtered to avoid recursive `web-agent` loading.
- `POST /api/chat/stream` emits one browser-facing NDJSON object per line for status, thinking, assistant deltas, tools, done, and errors.
- `web/pi-web-ui/` builds a dark React/Tailwind UI with fixed header, status strip, scrollable transcript/current run, and fixed footer composer.
- Reset creates a brand-new browser `sessionId`, clears frontend transcript/current-run state, and disposes the old backend session.

## What We're NOT Doing

- Optional OIDC login flows in the first iteration.
- Persistent browser-session storage on disk.
- Raw passthrough of native `AgentSessionEvent` objects to the browser.
- Markdown-only rendering for tool activity.
- Shared monorepo package for backend/frontend types.
- Separate backend workspace/package extraction beyond `.pi/extensions/web-agent/`.

## Testing Strategy

### Automated

- Backend static checks by file inspection:
  - `grep -R "timingSafeEqual" .pi/extensions/web-agent/auth.ts`
  - `grep -R "application/x-ndjson" .pi/extensions/web-agent/index.ts`
  - `grep -R "SessionManager.inMemory" .pi/extensions/web-agent/session-store.ts`
  - `grep -R "extensionsOverride" .pi/extensions/web-agent/browser-loader.ts`
- Frontend build after Phase 6:
  - `cd web/pi-web-ui && pnpm install && pnpm build`
- Frontend protocol checks by file inspection:
  - Confirm `x-pi-web-token` appears only in API auth helper usage.
  - Confirm `sessionStorage` is used for token and `localStorage` for `sessionId`.
  - Confirm `TextDecoderStream` is used in the NDJSON reader.

### Manual Testing Steps

1. Start Pi in the repository and confirm the web-agent status widget displays URL and token.
2. Request `GET /health` without a token; expect 200 with coarse server info.
3. Request `/api/session/meta` without or with an incorrect token; expect 401.
4. Request `/api/session/meta` with the correct token and no `sessionId`; expect a fresh `web_*` session id.
5. Create two browser session ids and verify title/meta/history isolation.
6. Verify browser-session loader excludes `.pi/extensions/web-agent/index.ts` while still reporting other resources.
7. Start a chat stream and validate one JSON object per line.
8. Verify assistant text, thinking, tool start/update/end, done, and error records map into the UI correctly.
9. Stop an active stream and verify abort behavior.
10. Reset and verify new `sessionId`, cleared frontend state, and disposed old backend session.
11. Build the SPA and confirm the backend serves `dist` assets and SPA `index.html` fallback.

## Performance Considerations

- Session lookup must be O(1) by `sessionId`, with TTL cleanup running on an interval rather than scanning per request.
- Stream translation should write NDJSON records incrementally without buffering the full run in memory.
- Current-run UI should mutate tool cards by `toolCallId` instead of rebuilding the whole transcript on each event.
- Metadata refresh should happen after `done` and on explicit reset/title actions, not after every text delta.
- Frontend NDJSON parsing should reuse a single buffer string and stream decoder to avoid excessive allocations.
- Static asset serving should use pre-built files from `web/pi-web-ui/dist` and avoid dynamic HTML generation per request.

## Migration Notes

No persisted schema migration is required in the first iteration. Browser sessions are intentionally in-memory only, so reset/rollback is implemented by disposing old sessions and re-creating isolated replacements.
